# 随机拍照

用于「随机拍照」「随机写真」「随机风格＋人物妆造」；旧「COS随机拍照」锁定第1类。普通指定内容生图、修图及双参考动漫转真人不自动掷骰。维护玩法只处理规则与文字资料。

## 先确认画幅与生图入口

收到新的随机拍照图片请求，先询问“这次用16:9、9:16，还是其他比例？”；其他比例由用户填写，如1:1、4:3、3:4。请求已经明确比例时直接采用，同一批或明确延续同一比例时复用已选比例。未知比例不能自行默认9:16或提交生图。只讨论规则、维护技能或只要文字方案时无需询问；文字方案标注比例待定。

正式写提示词前，按[模型识别与短提示词](random-photo-models.md)确认当前软件、所选模型与模式；不能确定用户使用什么模型时询问。比例与模型都缺失时合并问一次。查不到默认入口或没有可用模型时，继续完成抽样与妆造，联网提供服装参考图和完整提示词；交付方式见该文。

抽取时把已选比例传入 `--aspect-ratio W:H`。返回的 `requires_aspect_ratio` 为true时先补齐比例；`brief_ready` 为false时处理对应缺口。抽样就绪后仍需完成下方提示词编排。

## 独立随机与默认值

| 维度 | 未锁定时的抽法 |
| --- | --- |
| 妆造骰 | 六类各1/6：1 COS；2 战士；3 时尚/KPOP；4 清新/居家/成年青春感/浪漫；5 成人性感；6 古风/仙侠 |
| 来源骰 | 独立六面骰：1–4本地文字库，5–6当轮实际网络参考；妆造、现场与动作同源，明确混合来源时按职责记录 |
| 活动分支 | 80%主题活动；20%写真，写真内部通用与私房各50%，整体各10% |
| 主体媒介 | 默认四选一，各1/4；可锁真人/2D/3D/CG |
| 风格分支 | 80%单风格；20%双风格，独立于活动分支；两条20%同时命中约4% |
| 主风格 | 按主体媒介与妆造气质选择正向候选池，在池内唯一ID等概率；只在已审核的人物适用池内抽取；catalog同样使用该池，实际概率随锁定与适配条件变化 |

没有附加条件时，池的大小不改变妆造骰、来源骰或分支概率。明确锁定只剩部分可行路径时，报告实际条件概率。明确锁定主风格/媒介后，若登记路径仅支持单风格且用户未锁单双分支，先条件化为单风格并报告style_mix_probability=1/1；用户显式锁双风格仍报缺口，不临时拼出副风格。无此限制时保持原80/20。允许批次重复，种子复现文字方案，不保证图片一致。默认成年主角；画幅由用户当次选择，不预设比例。用户当前身份图控制长相及指定特征；未提供时生成普通成年人物。妆造参考中的脸不替代身份。

“骰子限定1–3”在既有COS测试语境指来源骰，不永久限制网络分支。用户指定类别、主题、分支、主副风格、区域、媒介、地点、动作或道具时保持指定项。单/双风格锁定覆盖风格80/20，写真锁定覆盖活动80/20。用户只需自然语言表达。

## 预先连接的活动池

运行时选择类别→妆造→主题→该主题已成立的活动套组。套组直接给现场、具体位置、动作、道具种类/数量/持有者/手部/状态以及人物关系；再从该套组的`shot_options`抽一个时机、机位、景别和观看重点。镜头不是全库独立乱配，它保持本动作的手部、重心与物件接触。场地与姿势不散抽后交给模型排查；模型只接收当前完整方案。

战士池含持枪警戒、交战、训练、巡逻、佩刀/拔刀、弓盾、检修、通信、休整及漫展剧情表演。时尚/KPOP池含街拍、秀场、机场、镜墙排练、编舞、手持麦/头戴麦演唱、签售/见面会及古建MV。COS、清新居家、成人性感、古风仙侠各有专属主题与通用/私房路径。

通用写真包含正式、窗边、环境与近距离肖像；私房含动作刚停的抓拍、汗湿、迷离神态和休息坐姿。保留当前妆造；汗湿根据可见皮肤与成像取舍表达，迷离描述神态，焦点另行安排。人物默认单人，仅登记互动带少量从属配角。

故事年代、环境风貌与取景情境分开。例如现代KPOP在古建拍MV可以成立；活动空间、落点和支撑保持，风格只改变登记区域的表现。

## 动作、机位与批次差异

随机拍照默认主动设计明显的动作与视角变化，适用于全部六类及主题/写真分支；安静动作仍可使用，但不能把正面、平视、站坐、小幅转头当作通用回退。先选动作事件与身体轮廓，再选能看清该事件的拍摄位置和瞬间。区分相机高度、相对方向、拍摄距离、景别和透视；只换焦距或同义词不算换机位。

可用变化包括起跳/落地、急转、跨步、俯身、后仰、伸展、蜷坐与仰躺；按衣装活动与实际支撑选择，不强迫每张运动。镜头可贴地、俯视、侧后方、肩后、穿过前景拍摄，也可保留平视。裁切、背影、侧脸、前景遮挡和运动模糊可成为创意；面部清晰要求只在脸实际可见且达到可辨尺度时适用，不为了验身份把远景拉近或背影扭回正面。用户明确要求正脸、全身或衣装展示时保留。

本地抽样仍保持原骰子/种子规则，允许底稿重复；最终编排默认做批次差异设计。比较本批与当前对话可见的最近已交付方案的动作轮廓、相机高度/方向、景别、人物占比和人景主次。高度相似时，优先改用当前套组另一成立镜头；仍相似时，将当次动作和镜头一起编排为定制套组，保留原类别、来源事实、衣装、主题、现场、分支、风格及用户锁定项，交代重心、手部、落点与道具接触。不能只改pose正文却留下旧activity/shot指令，也不能以换词冒充差异。显式锁定动作不改动作，显式锁定镜头不改镜头。

在最终创意目标中记录实际采用的动作/镜头与相对底稿的改动，出图按最终目标复核。网络观察保留原记录，原创镜头/动作改编另标，不称全部来自网络。此步骤是抽样后的创意编排，不是等概率无重复抽样；不重掷类别、来源、分支或风格，也不许通过额外生图试错去重。用户明确要求独立随机或重复构图时照办；受锁定限制无法拉开差异时如实说明。

抽中巨构场地或用户要求巨构时，读取 [巨构场景与拍摄](megastructure-scenes.md)。它是场地与拍法知识，不新增第七类妆造，不替换风格骰。显式巨构要求先定位已连接路径；库外方案按当次定制处理，不把普通场地直接贴上巨构标签。未指定时只在已连接场地路径中自然抽取，不把所有背景巨构化。

## 媒介池与双风格

通用原库保留620唯一ID供其他创作使用；随机拍照只读 `style-media-index.json` 中审核保留的 `styles`，移出项及原因记录于 `excluded_styles`，主副风格均不再选中。已连接主副关系见 `style-combinations.json`。运行用程序返回的本张条目，不把整库交给模型。

3D 与 CG 默认使用 `UE5 render style`，作为其区域的渲染风格意图，不宣称实际由 UE5 引擎渲染；保留已选风格的形体、材料、色彩与艺术表达。真人和2D不默认附加，混合媒介只作用3D/CG区域；用户明确指定其他渲染方向时以当次要求为准。

默认先抽主体媒介，再在该媒介与妆造气质的交集里抽风格。四种媒介都有实际主体表达：2D用绘制的脸、服装和空间；3D用立体形体与材质；CG用数字角色和合成空间；真人保留摄影人物。不能把2D/3D/CG只做成真人照片的外框。

`styling_families`连接妆造和风格的正向气质池：fresh、romantic、elegant、street、stage、athletic、martial、futuristic、classical、dark、playful、fantasy。先按本套衣装、角色和活动选用有依据的气质，再从兼容池抽风格；不为配合风格把清新妆改成浓烟熏妆。用户明确要求反差设计时，单独编排这张的融合方式，标记定制，不冒称已有登记组合。

服装题材风格还须与衣装的`style_affinities`直接连接，场地题材风格还须与现场直接连接。例如滑雪制服风格配其完整滑雪衣装，科学馆空间风格配登记的科学馆落点，不能凭共同的“古典/活泼”标签进入文职制服或私人卧室。原库这两类题材有配套原创文字卡和活动路径，原来的妆造和场地保持；新卡不冒充网络热门素材。主背景题材与副绘制语言可共同表达同一场地，两个不同地点不竞争同一背景。

默认`presentation=scene`：风格直接体现在人物、画法、光线或连续环境。适合人物主图的唱片封套、电影海报和编辑版式留在`layout`池；用户要求这类作品时使用。`any`开放两类，但不会重新纳入已移出的科学可视化、仪表界面、票据、产品包装和纯纹理。用户明确点名移出项时说明不在随机人物池，可作为普通指定视觉实验处理，不静默替换或重新放回随机池。当前数量由`stats`读取。

双风格先抽主风格，再在其登记组合和妆造气质的交集内抽副风格，组合多寡不增加主风格权重。真人＋漫画背景应在连续场景中可见，按相同透视、接触位置和主光方向融合，不能只放一个漫画贴纸；3D＋手绘空间等同理。人物身份、衣装结构、动作支撑与道具状态保持。摄影要求只作用摄影区域。

`catalog`为人物适用风格的跨媒介模式：按保留项的`full_catalog_medium`统计媒介权重，先抽媒介，再按实际妆造相容性选唯一风格ID。只在可行候选内报告条件概率，不宣称原库620项都参与。显式媒介锁使用普通媒介模式。网络取材仍先固定媒介和单/双分支，看到实际衣装、登记气质后才选风格ID。

## 程序与锁定

从本舱目录运行，脚本只读文字、不联网、不生图：

```text
python -B -X utf8 scripts/random_photo.py sample --count 1
python -B -X utf8 scripts/random_photo.py sample --class-id 1 --source-die 2
python -B -X utf8 scripts/random_photo.py sample --class-id 3 --theme-id theme-3-heritage-mv --source local --style-mix dual
python -B -X utf8 scripts/random_photo.py sample --source local --medium 2D --branch portrait --portrait-kind private
python -B -X utf8 scripts/random_photo.py sample --style-mode catalog --count 3
python -B -X utf8 scripts/random_photo.py stats
```

`--class-id/--class-die`锁类别；`--source-die`锁来源点数，`--source local|online`锁来源。省略`--medium`或用`--medium random`均随机四种主体媒介；`--presentation scene|layout|any`选择连续画面、版式或两者；`--style-mode catalog`人物适用跨媒介模式需不附媒介锁。`--branch themed|portrait`、`--portrait-kind general|private`锁分支；`--style-mix single|dual`锁风格分支。`--theme-id --activity-id --outfit-id --location-id --pose-id`锁内容，`--style-id --secondary-style-id --secondary-region`锁主副风格和副区域。道具由完整活动套组确定，可用 `--activity-id`锁对应配置。

已知妆造/活动ID反推类别；活动ID同时确定主题与分支。首次已知地点/动作等先在已连接路径中定位，剩余项按成立的条件池抽取，报告条件化概率。本地自动执行；网络已有当轮已查看候选池且尚未抽样时，使用`--online-stage initial`。已抽样后的网络回填用默认`resume`，候选不足不能改变原类别、分支或主题。没有附加锁时执行表中原始概率。冲突或无路径明确报错，保持骰点和锁定项，不重掷、降为单风格或偷偷换角。

库外位置、动作或道具在最终提示词编排时人工写成当次完整套组，注明定制，保留原骰点、衣装和风格；检查落点、支撑、手部和衣装关系。脚本只接受库内ID，不把临时名称传入`--activity-id`，不伪装网络观察，也不写回长期库。来源不能被本地文字方案冒充：网络尚未看图时仅保留类别、分支、媒介、单/双风格、主题与显式风格锁，`style_status=awaiting_outfit`；不凭未观察的衣装定风格ID。

返回 `needs_online_references` 时执行 [当轮联网](random-photo-online.md)。取得实际已查看候选后，在完整保留原抽样参数、种子和批次位置的情况下加 `--online-pool`；不要为消除缺口改骰或重选风格。

任何候选缺少有效 `shot` 或 `shot_options` 时 `requires_shot_plan` 为true，仍不可提交。补齐当次机位、时机、景别与观看重点，保持已看动作及其支撑，再用原抽样参数完成方案。

## 从抽样底稿到最终提示词

执行顺序：确认画幅与模型 → 抽取方案 → 补齐参考与完整妆造 → 设计画面 → 按模型写提示词 → 生图或交付参考与提示词 → 出图复核与修复建议。程序负责抽样与结构检查，执行者负责创意整合；把最终要达到的身份、衣装动作、主副风格区域、观看重点和光线效果记作本张创意目标，出图及修复沿用它；不为补齐妆发、光线或修复建议重掷骰子。

### 参考图职责与实际提交

每张参考在取材时确定职责：身份、服装、动作、场景或风格，默认一图一种职责。用户明确要求同图提供多个方面时才扩展；不能因为一张服装图里恰好出现姿势、地点或画风，就把它们加入本张方案。身份来自用户原始人物图，衣装来自已选造型，动作与场景来自已选活动套组，画风来自已选风格及作用区域。补找服装只补衣装依据，保留原骰点与其他已定项。

服装参考仅提取服装结构、配色、识别饰物与明确选用的道具外形；其中模特的长相、妆发、姿势、机位、背景、光线和画风不进入方案。道具外形参考也不决定握持方式，手部与使用状态按活动套组。

其他模特的整张穿衣照只供观察和文字提炼，不直接作为服装输入上传。优先选择服装商品图、平铺图或能完整保留必要衣装结构的局部图，排除模特脸与无关背景；不能隔离所需内容时，另找服装图或使用已观察的衣装文字，说明实际输入方式，不额外生图。裁切不能丢失本张所需的领口、袖形、下摆、配饰或道具结构。

提交前对照实际附件和最终正文：图号、职责及可见内容一致；服装输入只承担衣装，动作、场景、构图和风格仍对应本张方案。不能把“参考图2”写成整图复刻，也不能只靠末尾一句“不参考脸”替代输入处理。若工具只能使用会整体影响画面的普通图片参考，按上述方式处理输入并说明限制，不承诺文字就能完全隔离影响。各模型按同一职责分配编排。

### 身份与完整妆造

身份参考保留可辨认的脸型、五官比例及用户明确锁定的身体特征。原图的妆容、发型、发色、刘海、肤面光泽及布光不自动锁定；妆造参考中的脸不替代身份。只有用户明确指定保留时，才把这些外观项加入锁定。

妆容为人物、穿着打扮与活动服务。执行者先结合角色/版本、衣装气质、活动场景及主体媒介判断妆发是否协调，再写成一套服装、妆容、发型/发色、饰品方案；不把眼影、唇色、发型分别随机拼接，也不让版式或背景副风格擅自改变人物妆容。清新居家通常采用轻淡协调的妆发，不能仅为增加变化配性感烟熏妆；舞台妆与角色妆也不等于一律加浓。用户明确要求反差造型时保留其意图。

沿用文字卡或已查看造型中成立的设计；缺项在当次方案补齐，不把缺项交给身份图默认填充。最终正文写具体可见的妆发效果，不能只写“更换妆容”或“自然妆”。以眉色与眉形修饰、眼妆、唇色/光泽等必要差异表达造型，保留本人骨相与五官，不靠扩大眼睛、换鼻型或改变脸型模拟化妆。网络图未看清的部分注明原创补充，不冒充观察所得。

### 单张画面设计

`prompt_text`是包含画幅、活动套组、道具和风格的抽样底稿，不是可原样提交的最终提示词。`prompt_stage=creative_brief`及`requires_prompt_composition=true`要求执行者完成本节编排；`brief_ready`只表示抽样数据、比例和必要套组齐备，不代表已经完成妆发、画面整合或媒体验收。

保持已选衣装、位置、动作支撑、道具数量/持有者/手部状态及主副风格职责，把底稿编排为同一张画面。摄影区域明确一个主导光源及方向、有限受光区域、相邻暗区、焦点和前后距离；说明哪些信息保留、柔化或消失。光源可有多个，但主次、反射与遮挡要共同成立。不能把所有条目先拼满，再靠末尾重复“低调、柔和”修补矛盾；也不把提示词长度或词序当作效果保证。

编排时同时落实`rendering_intent`：人脸保留主要结构，头发用完整发束和连续轮廓，外围飞丝与逆光细线主动省略。确定哪片受光、哪片连为深暗，暗处允许失去纹理和次要形状；不逐区域提亮、不以全域微反差证明质感。真人按摄影规则，2D靠色面与笔触、3D靠大体块、CG靠数字绘画与合成明暗完成取舍。明确的高调或其他风格可改变整体影调，但不自动要求碎发、全域纹理或暗部恢复。模型专用参数仍只在对应入口使用。

各媒介区域分别落实：真人为摄影人物与可穿戴衣装，2D为线条/色面，3D为形体/材质，CG为数字艺术/合成。保留所选风格DNA及`visual_effect`：环境风格在连续空间体现，材料风格在有效范围的表面/装置体现，版式风格建立全幅排版，同时保留人物观看区域。局部副风格按登记区域融合，不用角落小饰品冒充主风格。纸张泛黄、印刷纹理等版式效果不自动铺到摄影人物皮肤上；确有整体印刷方案时明确作用范围和力度。

均匀闪光、监控低清等DNA按风格的登记区域表达；已登记的摄影例外由脚本解析到`region_targets`，不把被替换的默认目标、补救词、质量口号或旧示例附回正文。摄影参数与本张距离、焦点、曝光效果配对，不用相互矛盾的参数代替画面设计。非摄影区域不强套摄影影调、ISO或景深。

### 搭配成立后才可提交

`styling_families`只判断气质亲和，不证明具体服装、人物身份或场地成立。已登记的衣装/场地亲和与`required_scene_tags`必须在抽样时满足；显式风格锁也不能绕过。没有适合路径就报告冲突或缺口，不给普通客厅贴水下标签，不用“保留原场景”抵消风格正文要求的另一个地点。没有本地合适路径的风格可保留供有充分依据的网络候选使用，不伪造可达性。

最终写提示词前，按当前整套事实分别核对以下关系；发现冲突先修对应方案，未解决不能提交生图：

- 人物—服饰：身份、成年设定、角色版本及用户锁定特征一致，风格不换五官/年龄/身体结构；妆发配饰为当前衣装服务。现代人穿古装拍MV、COS在现代场馆可成立，不用年代不同自动判错；世界内剧情则按其叙事情境判断。
- 服饰—动作：裙摆、裤装、鞋、护甲、尾饰、头饰及佩挂物允许当前动作；不以粗粒度dynamic标签替代具体判断。握持、固定、支撑分别明确，识别配件不能无故消失，也不能为凑镜头临时发明。
- 场景—活动：人物实际处在可执行事件的位置，全部接触点、落脚面、器具与相机位置有依据。水边不等于水下，干燥地面不等于雪地，窗光摄影棚不等于洗衣店；支撑标签相同不代表地点可互换。
- 风格—整套内容：区分画法/介质/光色与具体题材。水彩或版画可以表现既有空间；港口、校服、自助洗衣等具象要求必须有相应场景或衣装支持。副风格只能在既有场景和衣装上表达登记的媒介效果，不新增另一处背景、另一套服饰或未登记实体道具。
- 镜头—风格：要求高处固定俯拍的监控风格不能同时保留低机位仰拍；主副风格、镜头时机和焦点共同成立。`shot_requirements`是风格明确前提；若存在，抽出的镜头只作底稿，`requires_shot_plan`保持true、`brief_ready`为false，由执行者完成符合前提的定制镜头并核对全部锁定后才可提交。不能把false静默改成true，也不能重掷来逃避冲突。显式锁定的镜头与风格硬冲突时向用户说明并请其决定取舍。

通过条件是每一项成立，不以综合高分抵消硬冲突。发现未登记的实质冲突时，未被用户锁定的冲突项可在原类别、来源、活动分支和媒介下缩小到相容候选再选，并记录原因及条件化范围；这不是为了批次去重而重掷，也不宣称原始风格抽样未变。用户锁定项不能替换，无相容候选时说明缺口。`compatibility_review`和`brief_ready`是编排状态，均不证明实际成图通过；核对结论及修订后的动作/镜头写入本张最终创意目标。批次差异改编后重新核对受影响关系，不能为了不重复而突破衣装、场景与道具约束。JEV可分别筛这些维度，疑点回到原文确认，不把分数当作安全保证。

### 模型适配与摄影层

模型确认、短提示词格式和无可用模型时的交付统一执行[模型识别与短提示词](random-photo-models.md)。同一方案跨模型时保持身份、妆造、活动、道具及风格目标一致，分别调整表达方式、参考输入和实际支持的参数。

通用创意与模型适配分开。现有[默认生图摄影规则](default-image-photography.md)及`built_in_photography_targets`是默认内置摄影入口的专项适配，沿用该文的适用边界；字段是短目标清单，不是可追加的提示词段，也不表示所有平台的默认模型通用。对匹配入口，以`region_targets`为本张逐区域目标；`style_overrides`说明哪些默认项已被风格替换，`targets`仅是各摄影区域共同目标。未替换项继续生效，不能再整段追加原始摄影模板。Nano Banana、即梦、Seedream及其他模型按各自任务适配，不复制这套专项压制词。

`photography_scope.layers`逐层记录媒介和职责，`regions`与`excluded_art_regions`引用具体层ID；主背景与副景片即使都在背景，也各自独立。现场环境只包括未被单列风格占用的部分，不能借“环境”把漫画背景重新纳入摄影。真人＋漫画背景分别表达，2D人物＋摄影陈列物仅对陈列物施加摄影要求。面部焦点、皮肤和头发要求仅作用于摄影人物层；物件摄影只处理材质、反射、空间与成像。摄影人物的皮肤以柔和偏哑光漫反射为主，鼻尖/颧骨少量局部反光，肤色随受光与遮挡变化；柔化微纹理，保留体积与眼部焦点。光泽妆、汗湿按所选妆造或用户要求局部表现，不覆盖全脸油膜，不用磨成均匀平面、追加毛孔或颗粒替代反光处理。

### COS与写真保留项

COS卡保留角色、作品、版本和`official_status`；`text_interpretation`是成人文字演绎，`photo_observed_cosplay`只证明看过造型，均不冒充官方原画。本地卡不足以确定角色版本、服装结构或关键识别点，或执行者不熟悉该造型时，按[补找服装参考](random-photo-online.md#补找服装参考与无模型交付)联网查找并实际查看图片，与原始身份图共同作为生成参考；保留角色、版本与骰点。用户明确禁止联网时说明缺口，交付有依据的文字方案，不猜成精确还原。COS真人按本张景别与观看重点选择景深：近距离人像可采用大光圈，较近且可见的眼睛准确对焦；动作全身、环境叙事和巨构远景允许更深景深。身份保持不强制每张正脸或可辨五官；背影与微小人物按实际可见轮廓和服装识别，不承诺不可见的人脸已验证。识别结构不要求整脸、全服装同时受光，也不要求逐根锐化头发。

COS默认左下角小面积原创手写角色原名，适用时加英文名，不遮挡人物、不做官方Logo。用户要求无文字或不要署名时省略；执行者自行添加的通用“无文字”词不能覆盖默认署名。其他类别不自动署名。

私房`shot`的时机、机位、景别、观看重点与动作/支撑共同执行，不用全身衣装展示覆盖近景或私房套组。酒店/休息室是地点，不自动改变活动分支。网络套组中的实际观察与原创镜头补充分开记录。

最终提示词与实际附件准备完后，核对本张语义：身份与服装职责是否分开，妆发是否为衣装活动服务，光线与媒介区域是否一致，适用的`region_targets`是否落到具体受光、焦点与信息取舍，以及比例、骰点、活动、道具和署名是否保留。已替换的默认项不能从别的模板重新加入；按含义判断，不用固定词是否出现作为通过依据。若使用JEV，提供这些具体证据与问题，不能只以字段齐全或重复“通过”代替判断；主执行者负责最终整合。

## 出图复核与修复建议

用户要提示词便交完整文字；要图片且入口可用便实际调用、取回、查看并交付，入口不可用则交服装参考图与完整提示词，并说明图片尚未生成。按批次位置报告真实类别骰、来源骰和风格ID，修补不计新抽样。实际对照身份图、完整妆造和本张画面目标，核对服装参考是否越界带入姿势、场景、构图或画风，再检查五官/眼神/肢体、服装道具、面部焦点、受光与空间融合、皮肤/头发、颗粒和风格/署名。程序检查不替代看图，维护规则不自行生图验证。

按`delivery_requirements`在最终回复交出逐张结论；有影响使用的偏差，直接附完整修复提示词、建议模型及参考顺序，不以“已保存”或“可以修复”代替。复核、模型选择、完整修复提示词与参考顺序统一执行[出图复核与修复](random-photo-review.md)。先报告影响使用的可见问题，再给能恢复本张创意目标的具体修改；不把有意的虚化、暗面、颗粒或艺术化判成缺陷。实际修复需要已有授权，不因出建议自动付费调用；完成同批已请求图片后一起交付，建议不阻塞其余图片。

## sexual提示与有限处理

记录工具返回，结合实际参考图和提交内容判断问题可能来自衣装、姿势、构图或其他上下文；`sexual`标签本身不能证明服装哪里需要修改。能定位时只调整有依据的部分，不能因标签自动补衣服，也不靠改名、隐去名字、添加“成年/无性化”声明规避拦截。身份与年龄描述须有依据。

衣装确需调整时，在原结构上选择必要的不透明内衬、开口收合或局部长度/侧片调整，保留角色的服装类别、主要轮廓、代表色、识别饰物与道具；标明“局部调整版”。姿势或构图有问题则修改对应部分，不连带换装。原因不清时说明不确定，保留原方案供用户选择，不凭猜测扩大修补。

有明确修改依据且仍在授权与调用额度内时，修订方案后最多重试一次，不承诺通过。文字无法表达必要衣装结构时，可在用户已授权参考图制作的范围内先做临时服装图，查看后再用于人物图；没有该授权便交文字修改稿。临时图不入本地库。

失败、服装参考和最终图均计入用户调用上限。调整后仍被拦截，或只能大改主要形象时停止；未锁定具体角色/服装的随机请求，可在剩余额度内另选同类别合规方案一次并如实说明，锁定项不擅自替换。结果未知先查原任务，不重复提交。

## 建库与扩充

本地只保存文字。按 [文字库与网络建库](random-photo-library.md) 同时采用原创设计与实际图像观察，保存来源和改编说明；六类有真实取材依据。不存原图、缩略图、模型或身份图片路径。本地正常运行直接用文字卡；COS造型不熟悉或无法调用生图时，按上方流程补找当轮服装图，原图仍不入本地库。新增关系与新增独立卡分别计数，组合数不冒充妆造数。
