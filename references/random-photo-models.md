# 随机拍照：模型识别与整合提示词

## 确认入口，复用有效选择

用户已指定软件、模型或默认入口时，沿用其选择，只核对当前可用能力，不重复询问。同批复用已确认入口；切换软件、版本或生成/编辑模式时，才更新工具说明、CLI 模型列表或界面已选项。确认型号不需要试生成。

未指定时使用当前软件已确认的默认生图入口；只显示“默认”就称“默认生图模型”，不猜底层型号。独立随机拍照 Skill 同样使用这个可移植名称，由所在软件的可用入口确定；只有确认是 Codex／ChatGPT 内置摄影入口才应用专项摄影规则，外部软件的未知默认模型不自动继承。

无法确认可用入口时，先完成创意 brief、参考职责与通用整合提示词，再询问用户准备使用的软件/模型；说明尚未生成图片，不静默改投其他模型。用户只要提示词时，不探测本机入口。

画幅、分辨率、画质、思考档位与参考权重只在当前接口提供时传入。同名模型在网页和 CLI 的能力未必相同，生成与修复路由遵循用户已确认设置。身份图须实际上传或按工具支持方式传入；提示词提到图片不等于已使用图片。

## 一个创意 brief，一份提交稿

先确定同一份人物身份、完整妆造、活动与道具、空间构图、光线、主副风格职责和画幅。brief 留作创意与修复依据，随后按实际模型写 **一份连贯、可复制的整合提示词**，不逐项转抄抽样 JSON、不并列堆叠多个模型模板。

身份图只定义同一人物的脸型、五官比例与用户锁定特征；服装图只定义已确认版本的衣装结构、配色、识别饰物及选用道具外形。妆发为人物、衣装与活动服务，不能用新的五官形容词重设计脸。姿势、场景、构图与画风由本张 brief 独立决定，不继承参考照片的照明、锐度和皮肤处理。

提交前执行[参考图职责与实际提交](random-photo.md#参考图职责与实际提交)：其他模特整张穿衣照不直接作为服装附件；图号必须对应真实上传顺序；没有附件就不写“图1”。新生成沿用用户原始身份图；普通修复只传待修复图，提示词开头锁定图中五官、脸型、比例和表情。仅在用户明确要求恢复原参考身份时追加身份图，具体按[修复交接](random-photo-review.md#修复交接是一份完整稿)。保留用户锁定项与需要的 COS 署名。

## 按模型组织正文

下列只是表达骨架。替换占位内容、删掉不适用部分，生成一份最终提示词；工具参数另外按真实接口传入。

| 入口 | 整合方式 |
| --- | --- |
| Codex／ChatGPT 内置生图 | 先明确身份与参考职责，再连贯描述妆造、活动空间、构图、风格及摄影效果。只有已确认摄影入口才使用[默认摄影目标](default-image-photography.md)。 |
| 外部未知默认模型 | 使用同一 brief 的直接视觉描述；不继承 GPT 专项压制规则，不臆造型号或参数。 |
| Nano Banana 2.1 | 新生成按身份、妆造、活动与媒介编排；真人质感修复读取[用户完整原文基底](restoration/nano-banana-2-portrait.md)，保留整份清理与积极增强表达，再补具体缺陷和必要风格保留项，不缩成局部弱化稿。Flow 输出尺寸按真实下载与文件尺寸核验，预览不冒充 2K。 |
| Seedream 5.0 Pro | 连贯说明人物、现场与风格职责；整体质感修复可采用[积极增强基底](random-photo-review.md#nano-banana--seedream-50-pro-单图质感修复基底)，与 Nano Banana 一样允许同时增强眼睛、发丝、皮肤和衣物，不继承 Image 2.5 的细节抑制要求；局部修复按实际范围写稿。 |
| Seedream 5.0 Flash | 同一内容压缩重复解释，保留身份、衣装识别点、动作和道具关系；适用模式与文字能力服从当前入口及已确认路由，不因短稿擅自切换模型。 |
| Midjourney 8.2／平台“美学模型8.2” | 用具体成图描述和当前入口支持的参考功能；实际 MJ 不加载“仿 MJ 美学”修图预设。普通图片参考会影响内容与构图，不承诺仅凭“同一个人”锁住身份。 |

通用中文骨架：

> [实际身份附件]定义同一人物，保留脸型、五官比例与[锁定特征]；[实际服装附件]仅提供[衣装版本和识别点]。人物采用[为衣装与活动服务的妆发]，穿[衣装]，在[具体场地与位置]做[动作、道具数量与占用关系]。[景别、视角、观看重点、空间距离与支撑]。[主风格如何作用人物和环境；如抽中副风格，描述大面积可见的媒介对照、透视、接触与光向]。[本张光色、焦点、成像质地与信息取舍]。[画幅、必要文字与署名]。

MJ 普通生成可将同一方案紧凑译为英文：

> [Medium and visual style], [subject with coordinated costume, hair and makeup], [action and prop relationships] in [setting], [composition, support and depth], [primary style and any selected secondary medium with coherent contact and light], [directional light, palette, focus and image texture]. [Required text and placement].

参考图通过当前入口支持的图片、人物或风格参考功能实际传入，职责仍按本次 brief。若入口确实支持 8.2 Edit Model，再用编辑表达：“Preserve [facial identity and other locked elements]. Change [authorized items and regions] to [concrete target]. [Costume reference responsibility, setting, action, composition, style and light].”不猜旧版参数、不默认强加 Raw 或高风格化数值。参考功能无法满足身份要求时说明限制，不能把匿名替身算作达标。

## 摄影目标与编辑交接

3D 与 CG 默认使用 `UE5 render style`，作为其区域的渲染风格意图，不宣称实际由 UE5 引擎渲染；保留已选风格的形体、材料、色彩与艺术表达。真人和2D不默认附加，混合媒介只作用3D/CG区域；用户明确指定其他渲染方向时以当次要求为准。

机位、动作与景别按最终创意目标适配，眼部焦点要求以脸可见且可辨为前提；背影/极远景不追加互相冲突的五官清晰指令。

engine 仅输出结构化 `built_in_photography_targets`，表达本张所需的低调受光、眼部焦点、柔成像、信息减量、细颗粒与距离关系；它是内部目标，**不把完整摄影规则作为长模板追加到提示词**。适配时将有效目标与本张创意合为自然正文，非摄影区域按其媒介表达，同时落实`rendering_intent`的发束合并、连贯暗区与信息取舍。最终正文写本张具体区域，不只列“柔和、低调”形容词。

模型模板只是提交起点，必须按实际出图验收。修复依据最初 brief 和实际待修图，按[实际看图与定向修复](random-photo-review.md)选择必要附件并写完整修复稿，不用“高清、锐化、磨皮”代替问题诊断。

查证版本与接口能力时使用当前官方资料：[Google 图像生成](https://ai.google.dev/gemini-api/docs/image-generation)、[Midjourney 版本](https://docs.midjourney.com/hc/en-us/articles/32199405667853-Version)、[Midjourney Edit Model](https://docs.midjourney.com/hc/en-us/articles/48495453462797-Edit-Model)。模板长度不保证模型表现优劣。
